# Leitlinien DHCraft

These rules answer the Leitfrage in [project.md](project.md): which rules DHCraft needs so that AI agents work lawfully, securely and verifiably in projects, research and programming. Each rule names the goal it serves (regelkonform, sicher, nachprüfbar) and its status (Pflicht, Vorgabe, Empfehlung, Ableitung), both defined in [INDEX.md](INDEX.md). The basis links to the stored original with its page. The summary of each source in [sources/summaries/](../sources/summaries/) gives the context.

| Rule | Goal | Status | Basis |
| --- | --- | --- | --- |
| No agent combines untrusted input, access to sensitive data and autonomous action. Where all three would meet, a human approves before the agent acts. | sicher | Empfehlung | [AEPD 2026, PDF p. 39–40](../sources/AEPD_2026-02_agentic-artificial-intelligence.pdf) |

| Agent changes to CI workflows and container files pin actions, images and installs to fixed versions, and the review checks this, because mutable tags and unpinned installs make up most security smells in agent pull requests and concentrate in GitHub Actions and Docker files. | sicher | Ableitung | [Security debt study 2026, PDF p. 2–3](../sources/arXiv_2026-07-19_security-debt-coding-agents.pdf) |
| Run an automated secret scan before every commit and push in agent-assisted work. | Merge agent-written code only after a person has reviewed it and checks show that it works (expected outputs, edge cases, tests). Running code is no evidence of correctness, and the developer remains responsible for agent-written components. | nachprüfbar | Empfehlung | [OpenSSF 2026, PDF p. 12](../sources/OpenSSF-CNCF_2026-05_securing-open-source-age-of-ai.pdf); [ReSA 2026, PDF p. 5](../sources/ReSA_2026-05-27_research-software-ai-assisted-development.pdf); [ReSA 2026, PDF p. 12](../sources/ReSA_2026-05-27_research-software-ai-assisted-development.pdf) |
| Give even small agent-built tools test coverage, automated security testing and documentation comparable to critical software, because human review alone comes under pressure as agent output grows. | nachprüfbar | Ableitung | [NCSC-UK blog 2026, section Getting security a seat at the table](../sources/NCSC-UK_2026-03-24_vibe-check-ai-may-replace-saas.md); [NCSC-UK blog 2026, section The promise of vibe coding](../sources/NCSC-UK_2026-03-24_vibe-check-ai-may-replace-saas.md) |
| Treat schema validation of agent-generated XML as necessary but insufficient. It shows structural conformity, while a person reviews whether the chosen markup fits the meaning of the text. | nachprüfbar | Befund | [JOHD 2026, PDF p. 5](../sources/JOHD_2026-03-02_llm-tei-encoding-evaluation.pdf) |
| Comments, issues and messages that an agent writes to people state that an AI agent wrote them and on whose behalf. | regelkonform | Ableitung | [Art. 50 Guidelines 2026, PDF p. 13](../sources/EU-Kommission_2026-07-20_guidelines-article-50-transparency.pdf); [Art. 50 Guidelines 2026, PDF p. 15](../sources/EU-Kommission_2026-07-20_guidelines-article-50-transparency.pdf) |
| Keep agent changes small and agreed with the people who review them, because large and uncoordinated agent pull requests fail more often and the share of pull requests with security smells rises with their size. | nachprüfbar | Ableitung | [Failed agentic PRs 2026, PDF p. 1](../sources/arXiv_2026-01-21_failed-agentic-pull-requests.pdf); [Failed agentic PRs 2026, PDF p. 2](../sources/arXiv_2026-01-21_failed-agentic-pull-requests.pdf); [Security debt study 2026, PDF p. 3](../sources/arXiv_2026-07-19_security-debt-coding-agents.pdf) |

## Sources outside the Leitfrage

The study on repository context files such as AGENTS.md measures task success and cost of coding agents, which concerns effectiveness and none of the three goals of the Leitfrage ([AGENTS.md study 2026, PDF p. 1](../sources/arXiv_2026-09-29_agents-md-context-files.pdf)). Its summary remains available for questions of effectiveness.
